## LEVEL 1 - Beginner

프로젝트 설명에 메모를 덧붙이는 일과 개인정보 보호 원칙을 지우는 일은 다르게 다뤄야 합니다. 14차는 문서 네 개가 어떻게 바뀌었는지 확인하는 로컬 검사입니다. 해시는 파일 바이트를 계산해 만든 지문 같은 값입니다. 사진에서 쓰레기를 더 잘 찾도록 학습하거나 수치의 진실성을 자동 판정하는 기능은 아닙니다.

| 문서와 예시 | 동작 | 확인 |
| --- | --- | --- |
| 프로젝트 개요·개발 내용에 설명 추가 | 가변 영역으로 허용 | 원래 v1을 남기고 예시 개정 v2 생성 |
| 안전경계의 공개 금지 문구 교체 | 불변 영역이라 거부 | CORE_MODIFIED 검사 |
| 관측사실 수치 사본을 크게 변경 | 제한 영역이므로 R2 위험도 하한 | 20% 변경률 자동 계산 기능은 없음 |
| 서로 다른 문서를 동시에 수정 | 두 변경을 병합 | 같은 문서를 다르게 고치면 충돌 |
| 원래 내용으로 되돌리기 | v2 다음에 v1 내용을 가진 v3 생성 | 과거 v1·v2를 지우지 않음 |

결과 폴더의 여섯 파일은 역할이 다릅니다.

버전 기록은 v1·v2·v3, 감사 기록은 각 버전을 만든 예시 행위, 입력 해시는 원본 네 문서의 지문, 모듈 내용은 실제 보존 텍스트, 검증 결과는 검사 목록, 실행 봉인은 출력과 현재 코드·정책을 묶은 지문 목록입니다.

봉인의 SHA도 따로 적어 두면 나중에 봉인 자체의 교체를 대조할 수 있습니다.

버전이나 감사 행·원본 입력·출력·코드가 달라졌으면 재검증에서 거부합니다.

먼저 Python 3.10 이상과 지정 DMF 원본을 준비한 뒤 아래 재현 명령을 따릅니다.

패키지 설치는 필요 없고 원본은 정확한 20 파일을 검사한 뒤 그 중 실제 Python 7 파일을 불러옵니다.

라이선스가 확인되지 않아 DMF 원문은 공개 사본에 포함하지 않았습니다.

입력 경로를 벗어나거나 문서를 중복 지정하거나 링크를 쓰면 거부하며 기존 출력 폴더도 덮어쓰지 않으므로 재실행에는 새 이름을 사용합니다.

실제 자료의 로컬 검사 14개, 어댑터 검사 10개, 원본 검사 18개가 각각 통과한 기록이 있습니다.

잘못된 문구·버전·감사 행을 만든 시험은 사본에만 수행했고 원본 네 파일은 전후 지문이 같습니다.

링크 검사는 실제 링크 생성 대신 속성 모사였으며 UTF-8·Python 구문 검사는 정적 타입·린트 검사를 대신하지 않습니다.

Shadow/local_validation_only는 이 예제의 상태이고 실제 운영 배포·교수 승인·Official 승격이 아닙니다.

G1~G9 전체 검사는 하지 않았고 DB·로그인·전자서명·KMS·외부 시간 인증도 없습니다.

같은 권한으로 코드와 기록을 전부 다시 쓰는 사람을 로컬 지문만으로 막을 수 없습니다.

기존 탐지 성능·학습·대시보드는 바꾸지 않았습니다.

### 실행·재검증과 근거

프로젝트 루트에서 Python 3.10 이상의 다음 명령을 사용합니다. 원본 경로는 고정 커밋 20 파일의 실제 위치로 준비하고 생성 출력은 아직 없는 새 디렉터리를 지정합니다.

```powershell
python -B -X utf8 "14차/실행검증.py" --dmf-root "14차/work/DMF원본" --input-dir "14차/자료" --output-dir "14차/새실행결과"
python -B -X utf8 "14차/실행검증.py" --dmf-root "14차/work/DMF원본" --input-dir "14차/자료" --output-dir "14차/새실행결과" --verify-only
python -B -X utf8 -m unittest discover -s "14차/tests" -v
```

두 번째 명령에 `--expected-seal-sha256`과 별도로 보존한 봉인 SHA를 추가하면 봉인 자체도 대조합니다.

## LEVEL 2 - Explorer

문서의 바이트 → 모듈 → manifest와 불변 봉인 → 버전 → 감사 행이 연결되는 구조입니다. 문서 내용을 숫자 형식으로 다시 저장하지 않고 원래 UTF-8 바이트를 해시합니다. 네 모듈 가운데 안전경계만 봉인 대상이며 관측사실은 제한, 개요와 개발내용은 가변입니다.

| 연결 | 핵심 역할 | 변경 때의 의미 |
| --- | --- | --- |
| 파일 SHA·ModuleRef | 내용 지문과 등급·순번 지정 | 관측 JSON의 소수 원값도 그대로 보존 |
| manifest/restrict_seal | 전체 모듈과 불변 모듈의 머클 루트 | 전체 설명 변경과 불변 경계 변경을 구별 |
| build_version | 이전 버전 해시와 내용 연결 | v2개 정, v3은 v2에 연결한 v1 내용 복원 |
| three_way_merge | base·두 사본 비교 | 독립 문서 병합, 동일 모듈의 다른 수정은 충돌 |
| AuditChain | 직전 감사 행과 버전 해시 연결 | 내용 변조·꼬리 삭제·빈 기록 불일치 탐지 |

가변 접촉은 R1, 제한 접촉은 R2 하한, 불변 접촉은 R3 하한과 별도 코어 제약에 해당합니다. 자동 예시는 불변 변경을 허용하는 승인 값을 만들지 않습니다. 제한 사본을 원문보다 큰 바이트로 바꾼 시험은 R2 확인용이며 API가 20% 변경률이나 승인 정족수를 집행했다는 뜻은 아닙니다.

여섯 결과는 버전 기록·감사 기록·입력해시·모듈 내용·검증 결과·실행 봉인입니다.

앞의 둘은 역사, 다음 둘은 입력과 실제 텍스트, 검증 결과는 14개 사례와 실제 임포트 근거, 봉인은 출력과 현재 소스·정책의 재대조 기준을 제공합니다.

세 버전의 부모·manifest 관계와 세 감 사 행의 target을 함께 읽습니다.

과거 버전·저장 manifest·봉인 필드·감사 actor·꼬리·원본 입력·출력을 바꾼 통제 사례에서 탐지를 확인했습니다.

재현에는 Python 3.10 이상과 고정 커밋의 DMF 20 파일이 필요하며 외부 패키지는 없습니다.

불러오기 전에 정책 SHA·각 파일 크기·Git blob·SHA를 확인하고 실제 임포트 7 파일도 대조합니다.

원문은 라이선스 미확인으로 공개에 포함하지 않았습니다.

아래 명령에서 입력·원본·새 출력 경로를 지정하고, 기존 결과에는 verify-only와 별도 보존 봉인 SHA로 재검증합니다.

경로 탈출·중복·링크·보호 경로 겹침·기존 출력 덮어 쓰기는 거부합니다.

관측된 14개 실행 검사와 어댑터 10·원본 18 검사는 다른 묶음이며 학습 성능 검사가 아닙니다.

링크 속성 모사와 UTF-8/AST 검사 범위 및 미설치 타입·린트 도구를 구분합니다.

Shadow는 로컬 표식이고 실제 트래픽 병행 관찰·G1~G9·사람 승인·DB/OIDC/KMS/서명·외부 앵커는 미구현 또는 미수행입니다.

같은 권한의 전면 재작성은 로컬 봉인만으로 인증할 수 없으며 기존 학습과 화면은 그대로 둡니다.

## LEVEL 3 - Practitioner

재현자는 고정 DMF 20 파일과 입력 네 문서 및 Python 3.10 이상을 준비합니다.

라이선스가 확인되지 않은 upstream 원문은 공개 저장소에 포함하지 않으므로 링크된 커밋에서 이용 조건을 확인해 로컬에 준비해야 합니다.

별도 pip 패키지는 필요 없습니다.

아래 세 명령은 프로젝트 루트에서 새 생성·읽기 전용 재검증·어댑터 회귀를 수행합니다.

| 확인 순서 | 사용할 결과 | 수락 조건과 실패 처리 |
| --- | --- | --- |
| 입력 선택 | 입력명세·입력해시 | 개요/개발 free·안전 immutable·관측 restricted, 네 파일 SHA 보존 |
| 원본 확인 | 검증 결과.upstream | 고정 20 파일과 실제 임포트 7 파일 SHA 일 치, 바뀐 코드로 대체 금지 |
| 새 생성 | 버전기록·모듈내용 | v1→v2→v3, v3 부모=v2·내용=v1, 기존 디렉터리 사용 금지 |
| 이력 확인 | 감사 기록 | 3 행이 세 버전 해시를 target으로 참조 |
| 검사 확인 | 검증 결과 | 로컬 14개 PASS, 어댑터 10·원본 18 기록과 별도 구분 |
| 보존 재검증 | 실행봉인 | 입력·출력·현재 코드·설정·검사 소스 대조, 봉인 SHA 별도 보관 권장 |

합쳐 여섯 JSON 파일을 보존해야 합니다.

생성 성공은 종료 0, 경로·해시 등 검증 거부는 1, 명령 인자 구문 오류는 2입니다.

실패하면 원문 오류를 보존하고 누락된 원본·경로·변경 파일을 확인합니다.

기존 결과 폴더나 봉인을 지우거나 현재 해시로 기준을 바꾸어 통과시키지 않습니다.

재실행은 다른 새 폴더를 쓰고 링크·중복·경로 탈출·원본/입력/설정과 겹치는 출력은 피합니다.

검사 안의 정상 개정은 메모 사본을 더한 R1 예시이고 불변 안전 문구 변경은 거부됩니다.

제한 관측사실의 합성 대폭 변경은 R2 하한을 확인할 뿐 20% 변경률 계산을 구현하지 않습니다.

독립 모듈 변경은 병합하고 같은 모듈은 충돌로 남깁니다.

롤백은 새 버전이며 소급 변조와 감사 수정·삭제, 저장 manifest·seal 변조는 실패해야 합니다.

원본 JSON 소수는 재계산하거나 canonical 메타데이터에 넣지 않고 파일 바이트로 보존합니다.

부록의 직접 실행 14·어댑터 10·원본 18 통과 기록은 G1~G9 전체 승인이나 탐지 모델 성능이 아닙니다.

링크 검사는 속성 모사, UTF-8·AST는 문법 범위이고 Ruff/mypy/Pyright는 미설치입니다.

Shadow/local_validation_only와 pending_human_review를 유지하며 실제 DB·OIDC·KMS·서명·외부 타임스탬프·사람 승인을 생성하지 않습니다.

봉인까지 같은 권한으로 다시 쓰면 외부 앵커 없이 인증할 수 없습니다.

이 절차는 기존 학습과 대시보드를 재개하거나 변경하지 않습니다.

### 실행·재검증과 근거

프로젝트 루트에서 Python 3.10 이상의 다음 명령을 사용합니다. 원본 경로는 고정 커밋 20 파일의 실제 위치로 준비하고 생성 출력은 아직 없는 새 디렉터리를 지정합니다.

```powershell

python -B -X utf8 "14차/실행검증.py" --dmf-root "14차/work/DMF원본" --input-dir "14차/자료" --output-dir "14차/새실행결과" --verify-only
```

| 과거 설명으로 되돌리기 | 허용 | v2 다음에 v1 내용을 가진 v3 생성 |
| 관측 수치의 원본 파일 변경 | 재검증 거부 | 실행 때 저장한 입력 해시와 불일치 |

[사용법](../../14차/docs/사용법.md)에 따라 원본 DMF와 입력 자료를 준비하고 새 결과 폴더를 지정합니다.

실행 후 검증 결과 JSON의 상태와 검사 수를 확인하고, 버전 기록에서 세 버전이 연결되었는지 살펴봅니다.

원본 자료는 덮어 쓰지 않습니다.

결과의 **Shadow는 이 예제의 로컬 상태**이며 실제 운영 배포나 사람의 승인이라는 뜻이 아닙니다.

이전 탐지 성능은 그대로이고, 운영 데이터베이스와 전자서명, 외부 시간 인증 및 G1~G9 전체 승격 검사는 아직 없습니다.

<a id="readme-reading-level-2"></a>
## LEVEL 2 - Explorer

DMF는 문서를 모듈 참조의 순서 있는 묶음으로 표현합니다. 파일 바이트의 해시와 변경 등 급, 순번을 각 참조에 넣으면 라이브러리가 전체 manifest와 불변 영역 봉인을 계산합니다. 버전 해시는 내용뿐 아니라 직전 버전의 해시도 포함하므로 되돌리기는 과거 기록을 지우는 대신 새 이력으로 남습니다.

| 계층 | 입력 | 연결 |
| --- | --- | --- |
| 내용 | UTF-8 원본 바이트 | 파일 SHA-256 |
| 모듈 목록 | 내용 해시·등급·순번 | manifest 머클 루트 |
| 불변 영역 | 안전경계 모듈 | restrict_seal |
| 버전 | manifest·봉인·직전 해시 | 버전 해시 체인 |
| 감사 | 버전 해시·행위·시각 | 직전 감사 행 해시 |

관측 사실은 제한 변경이어서 변경 시 R2 하한이 적용됩니다.

현재 API는 변경 비율을 세어 20% 초과를 판정하지 않습니다.

서로 다른 모듈을 고친 두 사본은 병합하고 같은 모듈을 서로 다르게 고치면 충돌을 반환합니다.

검증 예시에서만 사본을 고치며 원본 입력과 운영 학습은 건드리지 않습니다.

로컬 전체 기록과 코드까지 같은 권한으로 다시 쓰는 사람에 대한 외부 신뢰 경계는 제공하지 않습니다. [재현 절차](../../14차/docs/사용법.md)와 [세부 한계](../../14차/docs/적용범위.md)를 함께 확인합니다.

<a id="readme-reading-level-3"></a>
## LEVEL 3 - Practitioner

Python 표준 라이브러리만 사용하므로 패키지 설치 없이 실행합니다. [사용법](../../14차/docs/사용법.md)의 명령은 프로젝트 루트에서 실행하며 원본 DMF는 정확한 커밋의 20 파일이어야합니다. `configs/입력명세.json`에 선택된 네 입력만 읽습니다.

기존 출력 폴더를 지정하면 보존을 위해 거부하므로 재실행에는 다른 새 폴더를 사용합니다.

| 단계 | 작업 | 확인 |
| --- | --- | --- |
| 준비 | 고정 DMF 원본·입력 네 파일 준비 | 고정 커밋·해시 정책 일치 |
| 생성 | 실행 검증.py의 필수 세 경로 지정 | 새 결과 디렉터 리 생성 |
| 결과 | 검증 결과·버전 기록·감사 기록 읽기 | 14개 로컬 검사, 3 버전·3 감사 행 |
| 보존 확인 | --verify-only 실행 | 입력·출력·현재 소스·원본 재대조 |
| 회귀 | unittest discover | 어댑터 통합 검사 10개 |

정상 출력은 사람의 승인값을 만들지 않고 `pending_human_review`를 유지합니다.

오류를 만나면 기존 결과를 지우지 말고 원문 오류와 경로를 확인합니다.

출력 봉인의 SHA를 별도 기록에 보존하면 `--expected-seal-sha256`으로 해당 봉인 자체도 대조할 수 있습니다.

세부 산출물과 거부 조건은 [사용법](../../14차/docs/사용법.md)에 있습니다. 14개 로컬 검사는 G1~G9 전체 승격 검사나 탐지 정확도 평가가 아닙니다.

<a id="readme-reading-level-4"></a>
## LEVEL 4 - Advanced

연결 코드는 원본 소스의 재구현 대신 고정 원본을 검사한 뒤 API를 임포트합니다. 20 파일의 SHA-256·크기·Git blob SHA-1을 대조하고 실제 임포트된 7 파일의 경로와 SHA를 결과에 남깁니다.

입력과 출력 경로는 별도로 검사해 상대 경로 탈출, 중복 선택, 심볼릭 링크·재분석 지점, 하드 링크 및 기존 출력 덮어 쓰기를 거부합니다.

| 보호 지점 | 구현 선택 | 영향과 한계 |
| --- | --- | --- |
| 원본 변경 | 고정 정책 SHA를 코드에 결합 | 다른 upstream 임의 교체 거부 |
| 버전 생성 | Restrict를 build_version 전에 명시 호 출 | build_version 단독의 제약 누락 보완 |
| 이력 검증 | 문서 ID·순번·manifest·seal 재계산 | 저장 필드 변조 추가 탐지 |
| 감사 검증 | head 대조·빈체인 예외 검사 | 로컬 앵커 범위에서 절단 탐지 |
| 재실행 | 입력·현재 소스·정책 해시 대조 | 검증 뒤 수정에 기존 결과 재사용 방지 |

파일 쓰기는 새 디렉터리와 배타 생성만 사용합니다.

이는 데이터베이스의 단일 트랜잭션이나 동시성 CAS와 같지 않습니다.

재분석 링크 거부 회귀 검사는 실제 링크 생성 금지에 따라 파일 속성을 모사했으며 실제 링크 생성·해제 동작은 검사하지 않았습니다.

명시 범위와 실제 검증의 차이는 [적용 범위](../../14차/docs/적용범위.md)에 보존합니다.

## LEVEL 5 - Expert

기준 원본은 leecursion/DMF의 커밋 `cf550e3b2ceb0946ba89f64e43b7d6c2f5164383`, Git tree `906a2d35af5abe9449a417f2e3dbc740abb0e4e8`입니다. [고정 해시 정책](../../14차/configs/DMF고정해시.json)은 원본 20개 파일의 크기·Git blob·SHA를 담고 원문 코드는 포함하지 않습니다.

원본 라이선스가 확인되지 않아 코드는 로컬 비공개 참조로만 사용합니다.

| 검증 묶음 | 직접 실행 관측 | 구분 |
| --- | --- | --- |
| 실제 입력 실행 | 14/14 로컬 검사 통과 | 정상·합성 결함 사례의 기대 동작 |
| 어댑터 회귀 | unittest 10개 통과 | CLI·원본/입력/출력 변조·선택 경계 |
| 원본 라이브러리 | upstream unittest 18개 통과 | 원본에 포함된 검사 실행 |
| 텍스트·문법 | 소스 3 파일 엄격 UTF-8·AST 통과 | 의미상 무오류 보증 아님 |
| 정적 도구 | Ruff·mypy·Pyright 미설치 | 린트·정적 타입 검사 미수행 |

관측 사실의 소수 원값은 원본 바이트로 해시하고 JSON 숫자를 canonicalize에 넘기지 않습니다.

해시 메타데이터의 수치 관련 설명은 문자열로 남깁니다. upstream 위험도 API는 변경된 등급으로 하한을 반환할 뿐 정책 문서의 모든 승인 정족수와 20% 규칙을 집행하지 않습니다.

공식 승격·실제 DB/RLS·OIDC·KMS·외부 타임스탬프·서버 보증 신원 인증을 주장하지 않습니다.

동일 권한으로 코드와 모든 해시 기록을 일관되게 재작성할 수 있는 주체의 공격은 외부 앵커 없이 방어할 수 없습니다. [연결 코드](../../14차/dmf_adapter.py)·[검사](../../14차/tests/test_dmf_adapter.py)·[변경 기록](../../14차/변경기록.md)을 대조하고 독립 verifier 결과는 별도 절차에서 확인해야 합니다.
