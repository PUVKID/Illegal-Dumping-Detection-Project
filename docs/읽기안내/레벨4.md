<a id="level-4--용어와-실수하기-쉬운-구분"></a>

## 용어와 실수하기 쉬운 구분

| 용어·구분 | 뜻과 적용 범위 |
| --- | --- |
| 탐지와 해석 범위 | 객체 탐지는 영상에서 사람·쓰레기 같은 물체의 위치와 종류를 찾는 일입니다. |
| 용어와 실수하기 쉬운 구분 | 추적은 여러 화면에서 같은 물체를 이어 보는 일입니다. |
| 용어와 실수하기 쉬운 구분 | 의심 이벤트는 사람이 검토할 후보 장면이며 법적 위반 확정이 아닙니다. |
| 정밀도·재현율 | 정밀도·재현율은 탐지 결과와 정답을 비교하는 서로 다른 지표이고 mAP는 위치·분류를 종합하는 탐지 평가 값입니다. |
| 제공 자료 범위 | 검증 자료는 선택에, 고정 테스트는 최종 확인에 쓰며 출처·분할을 함께 읽습니다. |
| 탐지와 해석 범위 | 객체 탐지 수치는 CCTV 투기 행동 판정 정확도가 아닙니다. 정밀도·재현율 각 90% 목표와 실제 결과를 구분합니다. |
| 수신·원본 복구 | 화면·수신 복구·보고서 도구의 실행이 학습 완료를 뜻하지 않으며 Docker·데이터·가중치와 원래 동결 환경을 별도로 준비해야 합니다. |

### 데이터·학습·화면·복구·보고서를 나눈 구성

| 대상·조건 | 동작과 의미 |
| --- | --- |
| 관측과 해석 | 설정값과 처리 결과의 책임을 나누어 검토합니다. |
| 탐지와 해석 범위 | 초기 1·2차는 데이터 준비와 탐지 실험 노트북입니다. |

## 데이터·학습·화면·복구·보고서를 나눈 구성

초기 1·2차는 데이터 준비와 탐지 실험 노트북입니다.

최종/3차는 `data_pipeline.py`·`train_round3.py`·`inference.py`로 데이터·학습·추론을 나누고 `backend.py`·`launcher.py`와 화면을 연결합니다.

최종/4차는 기존 앙상블의 단일 프레임 확인 도구, 최종/최종은 HTML·CSV 성능 보고서입니다.

자료 종류가 달라 동일한 학습 실행 절차를 적용하지 않습니다.

7차의 `prepare_dataset.py`·`train_pipeline.py`·`worker.py`는 출처·준비·후보 학습을 연결합니다. training.json의 seed는 20261030이며 후보당 6시간, GPU 여유 18,000MiB·대기 7,200초, 체크포인트 여유 8GiB를 설정합니다. diverse_coco26l 후보는 이미지 960·batch4·60epoch·patience12·lr0 =0.0005, small_l_p2는 1280·batch2·45epoch·patience12·lr0 =0.0001을 구성합니다.

값은 계획이며 실제 완료 에폭과 다릅니다.

검증 선택은 TACO의 min(precision,recall)·F1과 PlastOPol의 min(precision,recall)·AP50 순서를 사용하고 동률에는 기준 모델을 유지합니다. full/full_grid3 정책을 검토하며 평가 이미지 1280·conf floor0.001·NMS IoU0.5·최대 1000개 탐지를 설정합니다.

다운로드·최소 여유 공간은 각각 100GiB입니다.

기존 평가와 독립 외부 평가의 출처·분할을 함께 읽어야합니다.

8·10차 화면은 7차 작업 상태를 읽어 현재 단계·대기·오류·재시도를 표시합니다. 9차는 상태 파일 교체 권한 오류 뒤 수신을 재개한 기록이고, 11차는 원래 7차의 동결 파일 16개를 확인하는 복구 도구입니다. 12차는 실험 종료와 결과·가중치 해시를 확인하고 report_core·report_outputs·watcher로 Word/PDF를 만드는 후처리 구성입니다.

화면이나 복구 도구 실행이 학습 완료를 뜻하지 않습니다.

3차 최종 보고서의 고정 테스트 150장·conf0.17·IoU0.50·ensemble/full 조건에서는 정밀도 61.36%·재현율 65.83%·F1 63.52%·mAP50 67.31%·mAP50 –95 45.70%를 기록했습니다.

목표 90%와 구분하며, 객체 탐지 수치는 CCTV 투기 행동 판정 정확도가 아닙니다. 단일 프레임 그림 역시 행동 판정이나 시험 지표 재계산 결과가 아닙니다.

## 주요 기술과 실행 구조

영상은 Ultralytics로 객체를 찾고 OpenCV로 프레임을 처리합니다. 작업 서버는 Linux의 파일 잠금과 프로세스 상태를 사용하며, 로컬 실행기는 Docker 안의 작업 코드와 통신합니다.

`backend.py`의 `TRASH_BASE` 기본값은 `/root/환경 PBL`입니다. 하위 `trash_round3/app`에 상태·업로드·결과 경로를 구성합니다. 로컬 실행기에는 기존 `2026-2` 컨테이너를 전제로 한 처리가 있으므로, 다른 환경에서는 컨테이너 이름·마운트·원격 경로를 함께 확인해야 합니다.

작업 상태와 선택 모델은 파일로 관리합니다. 영상 확장자와 허용 폴더를 확인한 뒤 첫 프레임·FPS·파일 크기 등을 검사하므로, 파일 복사가 끝난 다음 추론을 시작하는 흐름입니다.

<a name="-데이터-분리와-모델-선택"></a>
<a id="source-section-12"></a>
### 데이터 분리와 모델 선택

`data_pipeline.py`는 기존 사진 정체성과 라벨을 유지하고 검증·테스트 원본의 SHA-256을 대조합니다.

TACO 추가 사진과 pLitterStreet 입력을 수집하며, 기존 URL과 pHash 거리 6 이하의 근접 중복을 제외합니다.

작은 물체 확대 이미지는 학습 사진에서만 만듭니다.

다운로드 코드의 존재와 실제 데이터의 재배포 권한은 구별해야 합니다.

**단계:** 후보 학습

**최종 3차 코드의 설정:** YOLO26x·YOLO26l-P2, mix 각 180 epoch → focus 각 60 epoch

**단계:** 입력과 최적화

**최종 3차 코드의 설정:** 1536 픽셀, batch 2, AdamW, seed 20261013; GPU 메모리 부족 시 batch 1 재시도

**단계:** 고정 평가

**최종 3차 코드의 설정:** 검증 150장·테스트 150장; 평가 시 정확한 장수를 검사

**단계:** 추론 후보

**최종 3차 코드의 설정:** 전체 이미지, 전체+2×2 타일, 전체+3×3 타일; 중복 상자 NMS IoU 0.5

**단계:** 선택 기준

**최종 3차 코드의 설정:** 검증에서 min(정밀도, 재현율), F1, mAP50 순으로 선택

**단계:** 최종 테스트

**최종 3차 코드의 설정:** 선택한 모델·정책·신뢰도를 고정한 뒤 평가; 테스트 뒤 재학습 없음

**단계:** 목표 판정

**최종 3차 코드의 설정:** IoU 0.50에서 정밀도와 재현율 각각 0.90 이상인지 검사


이 표는 실험 설정과 판정 기준입니다. 이전 차수는 축소 입력을, 후속 평가는 원본 해상도를 사용합니다.

<a name="-영상에서-의심-장면을-만드는-조건"></a>
<a id="source-section-13"></a>
### 영상에서 의심 장면을 만드는 조건

`detector.Events`는 쓰레기 상자를 IoU 0.25초과로 연결하고, 정지 기준 상자와 IoU가 0.55 미만이면 정지 시간을 다시 셉니다.

기본 설정에서 기존 물체는 초기 10초 이내에 3회 이상 관측되고 기준 위치에서 최소 2초 정지하면 제외됩니다. 새 물체는 20초 이상 정지하고, 주변에서 한 번 이상 관측한 사람이 마지막으로 보인 뒤 5초 이상 지나야 후보가 됩니다.

최소 3회 관측과 한 번만 알림 조건도 적용합니다.

사람 발 위치와 물체 중심의 화면상 거리를 사용하므로 사람의 소유 관계나 투기 행위 자체를 인식한 결과는 아닙니다.

ROI는 0~1 좌표의 다각형으로 받고, 결과는 `result.mp4`, 프레임별 `frames.csv`, 이벤트·설정의 `summary.json`으로 나뉩니다. `frames.csv`의 `new_candidates`는 해당 프레임에서 새로 생긴 수가 아니라 그 시점까지 누적된 이벤트 수입니다.

영상 중간 디코딩 실패는 완료로 처리하지 않습니다.

<a name="️-실행기와-보조-파일"></a>
<a id="source-section-14"></a>
### 실행기와 보조 파일

`launcher.py`는 127.0.0.1에만 바인딩하고 매 실행 난수 토큰을 사용합니다. Docker의 기존 `2026-2` 컨테이너로 작업 코드를 복사하며, 영상 업로드는 4GB 이하로 제한합니다. `--self-test`도 컨테이너 초기화와 파일 복사를 수행하므로 단순한 읽기 전용 검사는 아닙니다.

`data_pipeline.py`의 루트는 `/root/환경 PBL/trash_round3`로 고정되어 있습니다. `backend.py`의 `TRASH_BASE` 하나만 바꾸어 전체 프로젝트 경로가 이동하지는 않습니다. `fonts/NanumGothic-Bold.ttf`, 고정 분할 manifest, 데이터·가중치와 선택 모델 파일을 함께 준비해야 합니다.

`build_windows.ps1`은 PyInstaller로 화면·작업 코드·폰트를 묶는 도구입니다. `make_report.py`는 저장된 최종 평가로 그래프·CSV·HTML을 만듭니다. `finalize_round3.py`와 `finish_on_exit.py`는 특정 과거 작업 ID·폴더에 연결된 결과 보관 도구이므로 새 학습을 시작하는 일반 명령으로 사용하지 않습니다.

<a name="-초기-실험과-외부-taco-코드"></a>
<a id="source-section-15"></a>
### 초기 실험과 외부 TACO 코드

1차 노트북은 YOLOv8m을 150 epoch·입력 960·batch 16으로 설정하고, TACO와 Amsterdam 자료를 출처별 무작위 80/10/10으로 나눕니다.

이 분할은 후속 코드의 중복 그룹 관리와 같지 않습니다.

초기 영상 결과에는 투기 행위 정답 라벨이 없으므로 정지·추적 조건을 만족한 장면은 검토 후보로 해석합니다.

초기 재개 JSON도 모델·영상·설정해시에 결합되어 있지 않습니다.

`데이터/taco/`의 외부 코드는 Pedro F.

Proença와 Matterport 계열의 MIT 라이선스 Mask R-CNN 구현입니다.

TensorFlow 1·Keras 2 기반이며 클린 뷰의 PyTorch·YOLO 학습 코드와 개발 귀속·성능을 구분합니다. `detector.py`는 train/test/evaluate(COCO segmentation) 명령을 제공하고, 세 노트북은 통계·전처리·anchor/ROI 탐색을 다룹니다.

TACO의 `requirements.txt`만으로 TensorFlow·Keras·imgaug·scikit-image·SciPy·pycocotools·h5py가 모두 충족되지는 않습니다.

코드의 최소 버전 검사는 TensorFlow 2·Keras 3 호환성 보증이 아닙니다.

공개 사본에는 클래스 매핑 CSV와 원본 이미지·주석·가중치가 없으므로 해당 외부 예제를 바로 실행할 수 없습니다.

### 13차의 목적과 실제 확인

정적 파생 본은 7차 prepare_dataset.py를 보존하고 **check_overlay의 전체 텍스트·AST 비교**로 변경 범위를 제한합니다. 단순히 정규식 한 줄만 교체했다고 설명하면 ROOT와 원본 SHA 보존 및 실행·보고서 바인딩의 의미를 놓치므로 네 경계와 두 단계 동결을 함께 검토해야 합니다.

| 구현 경계 | 구체 동작 | 차단하는 문제 |
| --- | --- | --- |
| 파생 네 지점 | legacy_match import 추가·ROOT를 7차로 지정·ID 호출 교체·원본 파일 SHA 명시 | 함수·상수·분할·정규화·주석·공백·개행의 추가 변경 |
| legacy_match/provenance _map | 마지막 basename을 plitter 또는 street·양의 정수·jpg로 fullmatch 하고 공식 주석 대조 | 부모 경로 숫자·선행 0·확장 자 꼬리·중복·공식 ID 미확인 |
| _source _binding | 제품 canonical·base/실효/resolver·공식 입력·이전 작업 결합 | 원본 preparation_sha만으로 실효 전체를 검증하는 혼동 |
| prepare_bound/_prepared _binding | 준비 직후 입력 SHA 재대조, 별도 prepared.json에 manifest·base 계약 SHA 고정 | 준비 전 None을 뒤에 조용히 수정하거나 다른 manifest를 소비 |
| worker 연결 | 원래 start.lock/run.lock·worker 경로·resume_of·동일 작업 검증 | 중복 준비/학습·다른 시도 메타 삽입·과거 실패 삭제 |
| report_bridge | 12차 기본 완료 검사 후 validate_recovery·references 재검증, 본문 깊은 복사 보강 | 기존 검증 우회·참조 변조·원문 본문 수정·진행 중 성공 보고서 |

원장 집계는 prior 1,999, previous_round5 3,839, overlap 642, union 5,196입니다.

공식 metadata 대응과 과거 재인코딩 JPEG의 SHA를 구별하며 최대 2,048 축소도 보존 한계입니다.

캐시는 완성 파일의 크기·MD5·SHA·영수증을 다시 읽어 확인하고 새 네트워크 수신으로 회복하지 않습니다. train_pipeline.prepare만 실효 함수로 연결하고 run은 원래 함수를 호출하며 selected·tests·추론·평가는 바꾸지 않습니다.

실행 종료 시 연결을 복원하고 원래 두 후보 60·45 epoch·각 6시간 예산을 유지합니다.

검증 명령은 아래 공통 안내를 사용하고, 기동은 별도 비공개 계획과 외부 expected-canonical에 묶입니다.

기록된 Windows 43 검사 중 POSIX 전용 1개 건너뜀은 Linux flock·/proc 검사를 Docker 43개 통과 기록과 분리해서 읽습니다.

보고서 연결 제어 사례는 합성 데이터로 base 실패·복구 실패·캐시 영수증 재사용·참조 변조를 확인한 것이며 실제 GPU 완료나 90% 보장이 아닙니다.

정상 완료 뒤에만 Word/PDF 두 파일을 새 최종 폴더로 연결합니다.

공개 복제 본에는 원래 자료·모델·계획이 없으며 7차 baseline 16 파일 중 11개 일치·2개 부재·3개 상이를 유지해 설명합니다. 현재 해시로 baseline을 바꾸지 않습니다. 로컬 해시는 같은 권한의 전면 재작성에 대한 서버 인증이 아니고, DMF 문서 병합·롤백은 14차의 별도 적용입니다.

#### 현재 공개 사본의 원본 대조

불변 Git blob과 original-baseline의 실제 대조에서 **7차 기준 16 파일은 11개 일치·2개 부재·3개 상이**입니다.

없는 파일은 docs/구현계획.md와 docs/설계.md이며, 다른 파일은 docs/이전검증분석.md·docs/출처와실험계약.md·tests/test_worker.py입니다.

상 이 파일을 모두 개 행 차이로 단정하지 않습니다. 10·12차 의존성을 포함한 전체 original-baseline 21 파일은 16개 일치·2개 부재·3개 상이입니다.

아래 보존 전문이나 과거 설명의 “16 중 13”은 이전의 불충분한 대조이며 현재 판정에는 이 재대조를 적용합니다.

원본 baseline과 과거 원문을 고쳐 결과를 맞추지 않습니다.

#### 검증과 원문 연결

보존된 13차 설치 폴더를 cwd로 사용해 `python -B -X utf8 -m unittest discover -s tests -v`와 `python -B -X utf8 verify_sources.py`를 실행합니다.

독립 검토에서 별도 보존한 SHA가 있을 때 `verify_sources.py --expected-canonical`의 값으로 지정합니다.

현재 값을 새 원본 기준으로 쓰지 않습니다.

이 문서 편집에서 검사를 새로 실행한 것으로 쓰지 않으며 위 숫자는 보존 검증 기록입니다.

### 14차의 목적과 실제 확인

어댑터의 신뢰 시작점은 **코드에 고정한 정책 SHA와 정책의 commit/tree·20 파일 바이트**입니다.

임포트 전에 SHA-256·크기·Git blob을 확인하고 캐시된 dmf_integrity 모듈을 제거해 검증한 src에서 다시 불러 온 뒤 실제 7 파일의 경로·SHA도 검사합니다.

JSON 확장자 내용은 UTF-8 바이트로 관리하며 관측값 float를 upstream canonicalize에 넘기지 않습니다.

| 함수 경계 | 실제 동작 | 별도 보완·제한 |
| --- | --- | --- |
| collect_inputs/selected_file/no_links | 명시 네 문서 선택·등급·중복·경로·링크 검사 | 원본 bytes 보존, 링크 속성 회귀는 모사 |
| load_upstream/source_hashes | 고정 정책·원본 검사 후 임포트, 현재 코드/CLI/config/tests 결합 | 소스 수정 후 과거 결과 재사용 거부 |
| check_restrictions/risk_floor | build_version 전에 불변 제약, R1/R2/R3 하한 계산 | 20% 변경률·승인 정책 엔진 아님 |
| verify_versions | 문서 ID·연속 순번·부모 및 manifest/seal 재계산 | upstream 단독 검사에서 빠진 저장 필드 비교 |
| three_way_merge/build_version | 독립 병합·동일 모듈 충돌, v2 다음 v1 내용 v3 | 원본 버전 수정·삭제 안 함 |
| verify_audit/verify _bundle | 감사 head·빈 체인·버 전 target·출력·입력·소스 대조 | 빈 체인/비영 앵커 추가 거부, 로컬 head만 사용 |

버전 기록과 감사 기록은 history, 입력 해시와 모듈 내용은 raw-content 대응, 검증 결과는 실제 14개 사례와 임포트 증거, 실행 봉 인은 여섯 출력 중 앞 다섯 파일과 현재 소스/정책·감사 head를 결합합니다.

봉인 SHA는 별도로 보존해 verify-only의 expected-seal-sha256으로 고정할 수 있습니다.

원본 JSON을 파싱해 다시 직렬화하는 대신 텍스트를 UTF-8로 재인코딩해 원래 content SHA와 대조합니다.

AST 검사는 Python 소스 문법 확인이고 입력 JSON의 의미 검증이나 정적 타입 검사는 아닙니다.

신규 출력 디렉터리와 파일의 xb 생성으로 기존 결과 덮어 쓰기를 막습니다.

이는 DB 트랜잭션·CAS·동시성 내구성 보장이 아니며 쓰기 실패의 부분 결과를 성공으로 간주하지 않습니다.

아래 CLI는 프로젝트 루트에서 지정 원본/입력과 새 출력을 받으며 검증 거부 1·인자 구문 오류 2·성공 0을 반환합니다.

경로 탈출·중복·링크·보호 경로 겹침과 원본 교체는 차단합니다.

외부 패키지 없이 Python3.10 이상이 필요하고 라이선스 미확인 upstream 코드는 로컬에만 둡니다.

실제 14개 검사·어댑터 10개·upstream18개 통과, UTF-8/AST 확인과 미설치 Ruff/mypy/Pyright를 구별합니다.

제한 모듈 대폭 변경은 합성 사례 R2이며 정상 R1개 정·불변 변경 거부·소급 버전/감사 변조·빈체인/절단·병합 충돌·입력 보존이 실제 14 사례에 포함됩니다.

Shadow는 local_validation_only일 뿐 G1~G9·Official·사람 승인·운영 DB/OIDC/KMS·외부 서명/시간 앵커가 아닙니다.

같은 권한으로 코드·정책·전체 기록·봉인을 재작성하는 공격에 대한 외부 신뢰 경계는 없고 모델 학습·추론·대시보드는 수정하지 않았습니다.

#### 실행·재검증과 근거

프로젝트 루트에서 Python 3.10 이상의 다음 명령을 사용합니다. 원본 경로는 고정 커밋 20 파일의 실제 위치로 준비하고 생성 출력은 아직 없는 새 디렉터리를 지정합니다.

```powershell
python -B -X utf8 "14차/실행검증.py" --dmf-root "14차/work/DMF원본" --input-dir "14차/자료" --output-dir "14차/새실행결과"
python -B -X utf8 "14차/실행검증.py" --dmf-root "14차/work/DMF원본" --input-dir "14차/자료" --output-dir "14차/새실행결과" --verify-only
python -B -X utf8 -m unittest discover -s "14차/tests" -v
```

두 번째 명령에 `--expected-seal-sha256`과 별도로 보존한 봉인 SHA를 추가하면 봉인 자체도 대조합니다.
