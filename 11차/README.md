# 🛠️ 11차 · 고정 실험 계약을 보존하는 다운로드 복구

[복구 설계와 한계](docs/복구설계.md) · [실행기](recover.py) · [회귀 검사](tests/test_recover.py) · [변경 기록](변경기록.md)

7차의 PlastOPol 원자료 수신이 4MiB 범위의 40초 경과 제한과 재시도 소진으로 멈춘 문제를 다룹니다. 제한에는 본문 읽기와 원장·상태 쓰기 시간이 함께 포함됐습니다. 현재의 작은 범위 응답 성공만으로 과거 실패가 네트워크 한 가지 원인이라고 단정하지 않습니다.

7차 코드 16개와 준비·원자료·학습 계약을 보존합니다. 새 실행기에서만 원자료 수신을 먼저 수행하고, 공식 크기·MD5·SHA-256 확인이 끝나면 원래 7차 준비·학습 함수를 호출합니다. 이미 받은 파일·부분 파일·전송 원장·체크포인트를 초기화하지 않습니다.

## 🔄 수신과 상태

범위는 64KiB에서 시작합니다. 10초 미만이면 최대 두 배로 늘리되 원래 상한 4MiB를 넘지 않고, 20초 이상이거나 진행 중 자발적으로 범위를 닫으면 줄입니다. 실제 수신량은 매번 기존 원장에 합산하며, 화면 통지만 약 2초 간격으로 합칩니다. 재시도와 해제는 즉시 전달합니다. 실제 통신 오류는 진행 유무와 관계없이 최대 6회만 재시도합니다.

공식 범위·크기·MD5·SHA·100GiB 전송 예산·100GiB 잔여 공간 검사를 유지합니다. 원장이나 디스크 반영이 불확실하면 요청 전에 남긴 `.recovery-pending.json`을 보존하고 자동 재개를 차단합니다. 기록을 감사하지 않고 삭제하거나 원장을 추정 값으로 갱신하지 않습니다.

## 🚀 실행 조건

실제 시작은 독립 검증 후 같은 Docker Linux에서 수행합니다. 고정 7차 작업자만 `--pipeline`으로 허용하며 `--start`가 새 작업을 만들고 기존 작업자의 중복 잠금·실패 기록을 사용합니다. 원래 화면은 같은 7차 작업 상태를 읽습니다. 이 저장소만으로 데이터·모델·GPU 환경이 설치되지는 않습니다.

```text
python -B -X utf8 11차/recover.py --pipeline 7차/worker.py --start
```

동결 검사는 `verify_sources.py --expected-digest <독립 검토한 고정값>`으로 실행합니다. `--print-digest`는 후보 계산이며 검증 영수증이 아닙니다. 실제 실행 인자·검사 결과·원격 반영은 별도 기록으로 확인해야 합니다. 이 차수의 작성만으로 다운로드·학습 완료나 정밀도·재현율 각각 90% 달성을 뜻하지 않습니다.
