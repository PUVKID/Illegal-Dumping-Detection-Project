# 마지막 실험의 보고서와 단일 완료 후 처리

## 범위와 성공 조건

진행 중인 지정 작업 하나만 읽는다. 학습과 다운로드 및 작업 상태를 변경하는 기능을 만들지 않는다. 7차와 10차 및 11차의 소스와 결과는 읽기 전용이다. 고정 본문은 별도 담당자가 작성한 report_sections.json을 사용한다.

정상 완료에는 지정 작업의 complete 상태와 작업에 저장된 result 및 final.json의 일치, 세 고정 테스트와 선택 계약, 데이터 manifest와 원본 코드 및 선택 가중치의 SHA-256 일치가 모두 필요하다. 과거 결과나 오래된 상태 및 Docker 중단을 완료로 간주하지 않는다. 실패 및 중단은 실제 오류와 미측정을 설명하는 별도 미완료 보고서로 남긴다.

## 읽기와 저장

10차 safe_io.py의 안전 공유 읽기를 동적으로 불러 JSON과 텍스트를 읽는다. 지정 job 파일만 60초 간격으로 관찰하며 별도의 학습 명령이나 Codex 및 언어 모델 API는 호출하지 않는다. 운영 설정과 저자 및 작업 식별자는 비공개 work에 둔다. 프로세스 잠금과 완료 영수증으로 중복 실행을 막는다. 기존 결과 경로가 있으면 덮어쓰지 않는다.

납품 폴더에는 Word와 같은 원고에서 변환한 PDF 두 파일만 저장한다. CSV와 차트 PNG 및 페이지 검토 자료는 12차 work의 비공개 지원 자료이다. HTML과 별도 원문 Markdown을 생성하지 않는다. 데이터와 가중치는 복사하지 않으며 위치와 해시만 기록한다. 실제 모델 결과의 PR 및 F1 곡선은 보존된 예측과 정답의 기존 일대일 IoU 매칭을 이용한다. 완료 epoch와 선택 checkpoint epoch를 구분하고 근거가 없으면 선택 epoch를 미확인으로 쓴다. TN은 객체 탐지에서 정의되지 않는다고 명시한다.

## 문서와 검증

나눔고딕 Bold를 적용하고 작성자의 관점으로 개발과 결과를 설명한다. 실제 정밀도와 재현율 목표는 각각 판정한다. 자체 AP와 공식 COCO API를 구분하며 CCTV 행동 정확도나 10차 영상 탐지의 새 가중치 적용을 주장하지 않는다. 제어 사례는 가상 결과임을 모든 출력에 표시한다.

검토한 명시적 렌더 설정으로 DOCX를 같은 원고의 PDF와 페이지 이미지로 변환한다. 설정이 없으면 blocked_renderer로 멈춘다. 현재 제어 사례의 모든 페이지를 시각 검사하고 실제 종료 후 자동 생성은 정합성 검사와 렌더 결과를 기록한다. 자동 렌더를 미래의 인간 시각 검토로 표현하지 않는다.

## 수리 1의 완료 계약 보완

독립 검토에서 테스트 사전의 첫 값으로 주목표를 판단하는 순서 의존을 확인했다. 주목표는 historical_taco 키로 명시한다. JSON 저장 순서가 달라도 같은 판정이어야 한다. 선택된 모델 및 각 테스트의 입력 크기와 confidence 하한 및 NMS IoU와 최대 탐지 수 및 평가기와 고정 프로토콜을 실제 7차 설정과 대조한다. 제어 사례는 각 항목 오염과 다른 테스트를 앞에 둔 순서를 재현하며 기대값을 완화하지 않는다.

## 완료 영수증 재사용

기존 영수증은 같은 지정 작업과 실제 출력 위치에 묶여야 한다. 정확히 두 문서의 존재와 경로 및 양의 크기와 SHA-256을 다시 확인한다. 정상 완료의 경우 현재 작업에 저장된 결과와 final.json의 일치 및 영수증의 최종 입력 해시도 대조한다. 파일 누락과 변경 및 입력 불일치는 blocked_invalid_receipt로 기록하며 기존 결과를 덮어쓰거나 실험을 다시 실행하지 않는다.
