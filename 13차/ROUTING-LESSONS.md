# 원본 ID와 실효 계약의 교훈

- 데이터 생성 코드가 기록한 이름 규칙과 후속 준비 코드의 정규식을 직접 대조해야 합니다. 경로 중간의 부분 문자열보다 basename 완전 매칭이 안전합니다.
- 공식 ID의 동일성과 파일 바이트의 동일성은 다릅니다. 이전 JPEG가 재인코딩됐다면 새 원본의 SHA로 이전 manifest를 갱신하지 않습니다.
- 고정 소스를 바꾸지 않는 어댑터도 실효 동작의 변경입니다. 원본 base 계약과 추가 실행 계약을 함께 검증하고 파생 소스·resolver·입력·계보·manifest를 결합해야 합니다.
- 준비 전에 알 수 없는 manifest SHA는 별도 준비 완료 영수증으로 동결해야 합니다. 기존 불변 계약의 빈 값을 나중에 갱신하지 않습니다.
- 같은 실험의 새 실행 시도는 실패 이력을 보존하며 원래 단일 작업 잠금과 프로세스 확인 경계를 유지해야 합니다.
- 상위 shell cwd와 실제 검사 subprocess cwd는 구분합니다. 등록된 검사 명세의 실제 작업 위치를 사용해야 모듈 검색 오류를 피할 수 있습니다.
- JSON 객체의 정렬 직렬화 SHA와 실제 파일 바이트 SHA는 저장 방식이 다르면 일치하지 않습니다. 물리적 LF 직렬화와 파일해 시를 대조해야 합니다.
- 보고서 소비자의 중첩 메타 형상은 실제 복구 검증 함수의 성공 반환값으로 통합 검사해야 합니다. 가짜 반환 객체만 맞추면 경계 오류를 놓칩니다.
