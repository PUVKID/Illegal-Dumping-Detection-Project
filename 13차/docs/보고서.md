# 재개 실험의 보고서 연결

## 기존 보고서와의 관계

12차의 결과 검증과 단일 작업 관찰 및 Word와 동일 원고 PDF 생성을 그대로 재사용한다. 12차 원본 파일은 변경하지 않고 13차 연결 부가 독립적으로 불러온 모듈에 검증과 본문 보강 함수를 연결한다. 보고서 생성기는 학습과 자료 수신을 실행하지 않는다.

## 완료 계약

먼저 12차의 정상 완료 및 세 고정 테스트와 선택 가중치 및 데이터·코드 해시 검사를 수행한다.

이어 재개 작업과 최종 결과의 13차 복구 메타데이터 및 실효 코드 계약을 검증한다.

비공개 계획의 recovery13_expected_canonical 값은 검사할 복구 계약을 지정한다.

기존 완료 영수증을 재사용할 때도 원래 두 파일과 최종 입력 바 인 딩뿐 아니라 추가 복구 계약을 대조한다.

## 본문에 추가할 사실

원래 7차 준비 코드 계약과 13차에서 실제 실행한 복구 코드를 구분한다.

보존 이미지의 ID 대응을 공식 주석과 저장 코드에 근거해 복구했다는 점을 설명한다.

과거 JPEG가 재인코딩됐으므로 당시 보존 파일의 SHA-256과 새 공식 원본의 SHA-256이 같다는 뜻은 아니며 모호한 ID를 추정하지 않는다고 기록한다.

이전 실패 시도와 미완료 보고서는 보존하고 재개 시도를 별도 결과로 연결한다.

이 복구를 성능 향상 또는 90% 목표 달성의 근거로 쓰지 않는다.

## 출력과 실행

기존 12차 ROOT와 7차 training 경로를 유지한다.

비공개 지원 자료는 12차 work의 새 고유 폴더에 두고 최종 두 문서는 기존 미완료 보고서와 다른 새 하위 폴더에 저장한다.

저자와 실제 작업 식별자는 비공개 계획으로 지정한다. 60초 관찰과 단일 작업 잠금 및 완료 영수증과 실패·중단의 비성공 판정은 유지한다.

실제 관찰 프로세스 기동은 검증한 실행 계획으로 별도 수행한다.

## 복구 메타데이터와 파일 대응

복구 모듈은 Windows에서 GPU 라이브러리를 불러오지 않는 validate_recovery(project, job, final, expected_canonical =...) API를 제공한다.

반환 객체의 meta와 references 및 provenance_counts와 limits를 사용한다. meta에는 새 작업과 이전 작업의 연결, 작업별 recovery13.json 경로와 계약해시, 실효 canonical과 기준·실효 준비 코드 및 ID 복구기의 해시가 있다.

실제 ID와 작업 식별자는 공개 코드에 고정하지 않는다.

references의 프로젝트 상대 경로별 SHA-256과 크기를 실제 파일과 다시 대조하고 기존 기본 계약과 충돌하면 거부한다.

검증한 대응은 12차 bundle의 references와 합쳐 비공개 입력 해시 영수증 및 문서의 파일 대응에 포함한다.

복구 계약과 ID 대응 원장은 작업별 13차 work/contracts 하위에서 읽는다.

원본 해시를 실효 코드 해시로 덮어 쓰거나 기본 검증을 생략하지 않는다.

## 제어 사례 검증

보고서 연결 부의 제어 사례는 기본 계약 실패와 복구 계약 실패 및 참조 파일 변조를 거부하고, 기존 영수증 재사용에서도 추가 검사를 실행하는지 확인한다.

진행 중 작업에서는 문서를 작성하거나 새 실험을 시작하지 않는다.

원문 본문을 깊은 복사로 보강해 기존 본문을 변경하지 않는다.

가상 시제품은 합성 결과임을 명시한 Word 와 동일 원고 PDF로 만들고 모든 페이지를 직접 확인하며 미래의 실제 결과 문서가 이미 검토된 것으로 표현하지 않는다.
