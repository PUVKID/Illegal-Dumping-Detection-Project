# 원본 ID 복구와 합성 실행 계약

## 확인된 원인과 성공 조건

보존 생성 코드는 공식 `image.id`로 `plitter_<ID>.jpg`를 만들지 만 7차 준비 함수는 `street_` 접두사만 찾습니다.

동일 공식 주석 ZIP과 이 전 주석 JSON 및 생성 코드를 대조해 1,999개 ID의 파일 명·경로·크기가 일치함을 확인했습니다.

새 원본과 과거 재인코딩 JPEG의 바이트 동일성을 대신 주장하지 않습니다.

성공 조건은 같은 준비·후보·검증·테스트 계획의 재개, 이전 실패 및 원본 소스·계약 보존, 모호한 ID 거부, 외부 동결 소스 guard, 같은 작업자 잠금, 실제 결과와 합성 계약의 보고서 검증입니다.

## 네 AST 변화

`effective_prepare.py`는 보존 7차 준비 파일의 정적 파생 본입니다.

ROOT를 실제 7차로 정하고, `legacy_match`를 가져오며, 문제의 ID 매칭 호출을 바꾸고, 준비 SHA 표현을 원본 `ROOT/prepare_dataset.py`의 명시적 해시로 바꿉니다. `__file__`을 위장하거나 전역 정규 식 모듈과 보존 row 값을 변조하지 않습니다.

전체 AST는 이 네 변화 이외의 함수·상수·분할·정규화 차이를 거부합니다.

원문 텍스트도 정확히 네 곳만 치환한 결과와 대조해 주석·공백·개행 변경을 거부합니다.

불변 JSON은 정렬한 UTF-8과 물리적 LF로 저장하여 ID 대응 메타의 SHA와 실제 파일 SHA를 일치시킵니다.

기존 `preparation_sha256`은 원 본 base 소스의 해시로 보존합니다. 실효 소스와 resolver의 해 시는 추가 `recovery13` 계약에 별도로 고정하며, base 계약 단독으로 전체 실효 동작을 검증했다고 표현하지 않습니다.

## 공식 ID 대응과 입력

파일 이름은 마지막 basename의 `plitter_숫자.jpg` 또는 `street_숫자.jpg`만 완전 매칭합니다.

부모 폴더의 숫자, 확장자 뒤 추가 문자, 선행 0, 모호한 공식 ID와 중복 대응은 거부합니다.

이전·현재 공식 주석 내용이 다르거나 보존 출처·SHA 형식이 다르면 거부합니다. 5차 source_id와 공식 이미지의 대응도 확인합니다.

source_contract는 이전 manifest·공식 주석과 ZIP·보존 생성 코드·5차 manifest·기존 준비 계약·수신 원장 및 네 공식 캐시의 고정해 시를 담습니다.

기동 전 전체 13차 제품 canonical과 원본 baseline을 대조합니다.

캐시는 이미 완성된 파일만 사용하고 실제 worker에서 크기·MD5·SHA를 다시 읽습니다.

네트워크가 필요한 캐시 부재는 새 수신으로 우회하지 않습니다.

## 실행과 단계별 동결

시작은 원래 7차 start.lock과 run.lock을 사용하고, 동시에 다른 준비·학습이 있으면 거부합니다.

기존 failed/interrupted 작업은 남기고 새 작업 ID와 resume_of를 연결합니다.

실제 argv에는 원본 7차 worker 경로와 --worker ID가 포함되므로 원래 Linux 프로세스 생존 계약을 유지합니다.

실제 명령과 canonical은 작업 기록에 남깁니다.

기동 전 소스·공식 입력·ID 대응·부모 작업해 시를 recovery13.json과 legacy_id_map.json에 동결합니다.

준비 전에는 source_frozen 상태이고, 유효 manifest가 생긴 직후 별도 prepared.json에 manifest SHA와 base 준비 계약 SHA를 결합해 prepared 상태가 됩니다.

None 값을 나중에 조용히 갱신하는 방식은 쓰지 않습니다.

실행 프로세스의 train_pipeline.prepare만 실효 준비 함수로 연결합니다. train_pipeline.run은 원래 함수를 호출하고, 결과가 저장 파일과 같을 때 새 recovery13 메타만 final과 job.result 양쪽에 동일하게 결합합니다. selected·tests·신뢰도·추론·평가 계약은 바꾸지 않습니다.

종료 시 프로세스 안의 연결은 복원합니다.

## 보고서와 한계

13차 보고서 연결은 12차의 기본 완료 검증 후 validate_recovery로 실효 소스·공식 입력·ID 대응·계보·준비 영수증·최종 manifest까지 추가 대조합니다.

실제 완성 전에는 성능이나 목표 달성을 만들지 않습니다.

Word와 PDF의 같은 원고·렌더·두 파일 납품·기존 결과 보존 규칙을 유지합니다.

로컬 해시와 영수증은 서버 신원 인증이나 같은 권한의 파일 변조 방지 경계가 아닙니다.
