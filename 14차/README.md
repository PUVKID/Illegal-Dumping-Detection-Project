# ICT 안전 문서에 DMF 적용

CCTV 불법 쓰레기 탐지 프로젝트의 설명과 안전 경계, 보존된 관측값을 **고정 커밋의 DMF Python 라이브러리**로 관리하는 14차 로컬 적용입니다. 새 모델 학습이나 탐지 성능 개선 작업은 아닙니다.

| 읽기 수준 | 출발점 | 바로 보기 |
| --- | --- | --- |
| LEVEL 1 - Beginner | 문서 변경과 보존을 처음 살펴보기 | [입문 설명](#user-content-reading-level-1) |
| LEVEL 2 - Explorer | 모듈·해시·버전의 관계 | [구조 설명](#user-content-reading-level-2) |
| LEVEL 3 - Practitioner | 설치 없이 실행하고 결과 확인하기 | [재현 설명](#user-content-reading-level-3) |
| LEVEL 4 - Advanced | 연결 코드와 실패 경계 검토 | [구현 설명](#user-content-reading-level-4) |
| LEVEL 5 - Expert | 고정 원본과 검증 범위 대조 | [전문 검토](#user-content-reading-level-5) |

| 입력 | 처리 | 결과 |
| --- | --- | --- |
| 프로젝트개요·개발내용 | 가변 모듈의 예시 변경 | v2 새 버전 |
| 안전경계 | 불변 모듈 해시 봉인 | 변경 거부 검사 |
| 관측사실 JSON | 원본 바이트 SHA-256 | 수치 원값 보존 |
| v1·v2 이력 | v1 내용을 v2 다음 새 버전으로 복원 | v3·감사 기록 |

<summary>LEVEL 1 · Beginner — 목적과 동작부터</summary>

<a id="reading-level-1"></a>
## LEVEL 1 - Beginner

쓰레기 탐지 프로그램의 설명을 고치더라도 개인정보 공개 금지나 평가 원칙까지 함께 바뀌어서는 안 됩니다.

이번에는 문서 네 개를 작은 관리 단위인 **모듈**로 나누었습니다.

각 파일의 바이트에 SHA-256이라는 계산을 적용해 내용을 나타내는 긴 값을 저장합니다.

파일이 바뀌면 값도 달라져 같은 내용인지 확인할 수 있습니다.

이 값은 문장의 사실 여부나 작성자의 신원을 증명하지는 않습니다.

| 예시 | 허용 여부 | 확인하는 것 |
| --- | --- | --- |
| 프로젝트 설명에 예시 개정 문구 추가 | 허용 | 기존 v1을 보존한 v2 생성 |
| 안전 경계의 문구 교체 | 거부 | 불변 영역 변경 발견 |
| 과거 설명으로 되돌리기 | 허용 | v2 다음에 v1 내용을 가진 v3 생성 |
| 관측 수치의 원본 파일 변경 | 재검증 거부 | 실행 때 저장한 입력 해시와 불일치 |

[사용법](docs/사용법.md)에 따라 원본 DMF와 입력 자료를 준비하고 새 결과 폴더를 지정합니다.

실행 후 검증 결과 JSON의 상태와 검사 수를 확인하고, 버전 기록에서 세 버전이 연결되었는지 살펴봅니다.

원본 자료는 덮어 쓰지 않습니다.

결과의 **Shadow는 이 예제의 로컬 상태**이며 실제 운영 배포나 사람의 승인이라는 뜻이 아닙니다.

이전 탐지 성능은 그대로이고, 운영 데이터베이스와 전자서명, 외부 시간 인증 및 G1~G9 전체 승격 검사는 아직 없습니다.

<a id="reading-level-2"></a>
## LEVEL 2 - Explorer

DMF는 문서를 모듈 참조의 순서 있는 묶음으로 표현합니다. 파일 바이트의 해시와 변경 등 급, 순번을 각 참조에 넣으면 라이브러리가 전체 manifest와 불변 영역 봉인을 계산합니다. 버전 해시는 내용뿐 아니라 직전 버전의 해시도 포함하므로 되돌리기는 과거 기록을 지우는 대신 새 이력으로 남습니다.

| 계층 | 입력 | 연결 |
| --- | --- | --- |
| 내용 | UTF-8 원본 바이트 | 파일 SHA-256 |
| 모듈 목록 | 내용 해시·등급·순번 | manifest 머클 루트 |
| 불변 영역 | 안전경계 모듈 | restrict_seal |
| 버전 | manifest·봉인·직전 해시 | 버전 해시 체인 |
| 감사 | 버전 해시·행위·시각 | 직전 감사 행 해시 |

관측 사실은 제한 변경이어서 변경 시 R2 하한이 적용됩니다.

현재 API는 변경 비율을 세어 20% 초과를 판정하지 않습니다.

서로 다른 모듈을 고친 두 사본은 병합하고 같은 모듈을 서로 다르게 고치면 충돌을 반환합니다.

검증 예시에서만 사본을 고치며 원본 입력과 운영 학습은 건드리지 않습니다.

로컬 전체 기록과 코드까지 같은 권한으로 다시 쓰는 사람에 대한 외부 신뢰 경계는 제공하지 않습니다. [재현 절차](docs/사용법.md)와 [세부 한계](docs/적용범위.md)를 함께 확인합니다.

<summary>LEVEL 3 · Practitioner — 준비·실행·결과 확인</summary>

<a id="reading-level-3"></a>
## LEVEL 3 - Practitioner

Python 표준 라이브러리만 사용하므로 패키지 설치 없이 실행합니다. [사용법](docs/사용법.md)의 명령은 프로젝트 루트에서 실행하며 원본 DMF는 정확한 커밋의 20 파일이어야합니다. `configs/입력명세.json`에 선택된 네 입력만 읽습니다.

기존 출력 폴더를 지정하면 보존을 위해 거부하므로 재실행에는 다른 새 폴더를 사용합니다.

| 단계 | 작업 | 확인 |
| --- | --- | --- |
| 준비 | 고정 DMF 원본·입력 네 파일 준비 | 고정 커밋·해시 정책 일치 |
| 생성 | 실행검증.py의 필수 세 경로 지정 | 새 결과 디렉터 리 생성 |
| 결과 | 검증 결과·버전 기록·감사 기록 읽기 | 14개 로컬 검사, 3 버전·3 감사 행 |
| 보존 확인 | --verify-only 실행 | 입력·출력·현재 소스·원본 재대조 |
| 회귀 | unittest discover | 어댑터 통합 검사 10개 |

정상 출력은 사람의 승인값을 만들지 않고 `pending_human_review`를 유지합니다.

오류를 만나면 기존 결과를 지우지 말고 원문 오류와 경로를 확인합니다.

출력 봉인의 SHA를 별도 기록에 보존하면 `--expected-seal-sha256`으로 해당 봉인 자체도 대조할 수 있습니다.

세부 산출물과 거부 조건은 [사용법](docs/사용법.md)에 있습니다. 14개 로컬 검사는 G1~G9 전체 승격 검사나 탐지 정확도 평가가 아닙니다.

<summary>LEVEL 4 · Advanced — 구현·설계·실패 처리</summary>

<a id="reading-level-4"></a>
## LEVEL 4 - Advanced

연결 코드는 원본 소스의 재구현 대신 고정 원본을 검사한 뒤 API를 임포트합니다. 20 파일의 SHA-256·크기·Git blob SHA-1을 대조하고 실제 임포트된 7 파일의 경로와 SHA를 결과에 남깁니다.

입력과 출력 경로는 별도로 검사해 상대 경로 탈출, 중복 선택, 심볼릭 링크·재분석 지점, 하드 링크 및 기존 출력 덮어 쓰기를 거부합니다.

| 보호 지점 | 구현 선택 | 영향과 한계 |
| --- | --- | --- |
| 원본 변경 | 고정 정책 SHA를 코드에 결합 | 다른 upstream 임의 교체 거부 |
| 버전 생성 | Restrict를 build_version 전에 명시 호 출 | build_version 단독의 제약 누락 보완 |
| 이력 검증 | 문서 ID·순번·manifest·seal 재계산 | 저장 필드 변조 추가 탐지 |
| 감사 검증 | head 대조·빈체인 예외 검사 | 로컬 앵커 범위에서 절단 탐지 |
| 재실행 | 입력·현재 소스·정책 해시 대조 | 검증 뒤 수정에 기존 결과 재사용 방지 |

파일 쓰기는 새 디렉터리와 배타 생성만 사용합니다.

이는 데이터베이스의 단일 트랜잭션이나 동시성 CAS와 같지 않습니다.

재분석 링크 거부 회귀 검사는 실제 링크 생성 금지에 따라 파일 속성을 모사했으며 실제 링크 생성·해제 동작은 검사하지 않았습니다.

명시 범위와 실제 검증의 차이는 [적용 범위](docs/적용범위.md)에 보존합니다.


</details>

<summary>LEVEL 5 · Expert — 근거·프로토콜·한계 검토</summary>

<a id="reading-level-5"></a>
## LEVEL 5 - Expert

기준 원본은 leecursion/DMF의 커밋 `cf550e3b2ceb0946ba89f64e43b7d6c2f5164383`, Git tree `906a2d35af5abe9449a417f2e3dbc740abb0e4e8`입니다. [고정 해시 정책](configs/DMF고정해시.json)은 원본 20개 파일의 크기·Git blob·SHA를 담고 원문 코드는 포함하지 않습니다.

원본 라이선스가 확인되지 않아 코드는 로컬 비공개 참조로만 사용합니다.

| 검증 묶음 | 직접 실행 관측 | 구분 |
| --- | --- | --- |
| 실제 입력 실행 | 14/14 로컬 검사 통과 | 정상·합성 결함 사례의 기대 동작 |
| 어댑터 회귀 | unittest 10개 통과 | CLI·원본/입력/출력 변조·선택 경계 |
| 원본 라이브러리 | upstream unittest 18개 통과 | 원본에 포함된 검사 실행 |
| 텍스트·문법 | 소스 3 파일 엄격 UTF-8·AST 통과 | 의미상 무오류 보증 아님 |
| 정적 도구 | Ruff·mypy·Pyright 미설치 | 린트·정적 타입 검사 미수행 |

관측 사실의 소수 원값은 원본 바이트로 해시하고 JSON 숫자를 canonicalize에 넘기지 않습니다.

해시 메타데이터의 수치 관련 설명은 문자열로 남깁니다. upstream 위험도 API는 변경된 등급으로 하한을 반환할 뿐 정책 문서의 모든 승인 정족수와 20% 규칙을 집행하지 않습니다.

공식 승격·실제 DB/RLS·OIDC·KMS·외부 타임스탬프·서버 보증 신원 인증을 주장하지 않습니다.

동일 권한으로 코드와 모든 해시 기록을 일관되게 재작성할 수 있는 주체의 공격은 외부 앵커 없이 방어할 수 없습니다. [연결 코드](dmf_adapter.py)·[검사](tests/test_dmf_adapter.py)·[변경 기록](변경기록.md)을 대조하고 독립 verifier 결과는 별도 절차에서 확인해야 합니다.

</details>
